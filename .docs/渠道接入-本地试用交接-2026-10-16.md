# 渠道接入：本地试用交接

日期：2026-10-16。交付者：Codex。

## 本次完成的内容

企业管理台新增实际渠道管理操作，不再只是企业微信配置记录表。

- **系统管理 → 渠道接入**：选择数字员工，分别管理飞书、企业微信和微信。
- **数字员工 → 详情 → 发布 → 管理渠道接入**：复用同一组件，直接管理该员工。
- 接入流程：启用渠道 → 等待 operator 更新生效 → 配置凭据或微信扫码 → 刷新状态 → 平台内发消息验证。
- 飞书支持 App ID / App Secret；企业微信支持长连接智能机器人的 Bot ID / Bot Secret；微信复用运行时已有的二维码、确认/验证码、取消及 Bot Token 接入。
- 提供凭据更新、重连、停用，以及休眠员工的唤醒入口。停用会移除该员工该平台的运行时凭据，重新接入时需重新配置。
- 配置状态与通道进程、平台连接状态分开。无状态数据时显示未知，不用“已配置”冒充真实收发通过。
- 新接口逐次复核企业管理员身份；服务端按固定路径访问该员工运行时。平台密钥不进入 CR，不回显到列表/详情，沿用运行时已有的持久存储。
- 补渠道专用内部授权：只允许受信企业服务管理渠道，不把普通内部聊天调用提升为管理员；聊天代理剥离客户端提交的渠道管理授权头。

“微信”与“企业微信”是两个渠道；微信账号与平台实际可接入性仍需在目标环境扫码验证。此次不接公众号、小程序或企业微信群 Webhook。

一期沿用每名数字员工、每个平台一份连接的运行时模型。试用时为不同数字员工配置独立机器人，不向多名员工重复填写同一机器人凭据；本次没有新增共享机器人的跨员工路由或全局机器人去重。

## 给本地部署 agent 的步骤

1. 先只读记录当前组件版本、员工 phase、CRD 和渠道模式，确认本机试用范围；保留已有凭据与运行时持久卷，不覆盖共享 Secret。如果现役源码包含其他尚未合入 main 的知识库等改动，在独立部署候选分支整合本次提交并验证，不直接以本次 main 基线覆盖现役版本。
2. 更新数字员工运行时，包含 `backend/app/gateway/channel_admin.py` 及两个渠道 router 的修改。仅更新 Portal/UI 而保留旧运行时，保存凭据会被拒绝，管理台会提示配套版本不足。
3. 更新治理 operator 及 CRD。新增 `spec.channels.wechat` 已在 operator base CRD、chart 和聚合清单同步；遗漏 CRD 会使微信开关被裁剪。沿用现有 Helm/CRD 发布流程，不由本交接自行改变 Helm 的 CRD 管理策略。
4. 更新 Portal，再更新 Admin Console。Portal/operator 为 Go 组件，按仓库规则优先 ko 构建；数字员工 Python 运行时按原有刷新层方式构建，不能用 ko 代替。此处不要求重做所有底层镜像。
5. 核对员工实际运行的 Gateway 镜像已更新，不仅是默认镜像参数已改。创建或选一名用于测试的常驻员工，先确认 `spec.hibernation.enabled` 为 false 或未启用，再在管理页面启用目标渠道，等待该员工 rollout 结束后刷新，出现“配置接入”可用状态。页面及 API 会拒绝休眠冲突，不会自动更改员工常驻策略。
6. 依次试飞书、企业微信或微信。真实凭据只在本机受控配置/表单中输入，不贴到聊天、Git、构建参数、测试截图或交接文档。微信扫码需要运行时单 Gateway worker，沿用上游 QR 会话限制。

本轮接入适配的是**员工内置渠道运行时**。若现场启用了独立 `channelGateway` / `CHANNEL_GATEWAY_URL`，不要同时拉起第二份机器人连接；先核对当前消费者和凭据归属。本次未实现独立休眠渠道网关的企业管理桥接，不能用这套 UI 的成功状态替代该模式验收。模式切换由部署负责人按现场授权和回退方案安排。

## 自审修复（初版后追加）

- **休眠冲突**：激活 API 在写 CR 前拒绝三平台与休眠的组合；operator 对三平台统一禁止缩零，不因仅配置 gateway URL 放行。管理员必须明确选择关闭休眠后再接入。已有 Error 员工可以尝试停用渠道恢复；仍要求运行时成功清理凭据，失败会保留开关并报错，不假报停用成功。
- **空密钥保留**：运行时现在将缺省密码字段解释为保留已有密钥；初次配置无旧值仍拒绝，显式空字符串仍拒绝，原有 `********` 标记继续兼容。补了三平台真实 HTTP router 的更新回归，不能只依赖 UI mock。
- **连接状态**：企微要求 SDK 已鉴权且 socket 打开；连接任务失败、断开、停止后不报 connected。微信要求近期一次成功的平台轮询；启动未握手、网络/平台错误、证据过期或任务退出均不报 connected。连接状态仍不代替真实消息收发验收。
- **语言传递**：渠道页和员工详情渠道面板使用调用方语言，默认沿用控制台 `ADMIN_LANGUAGE`；补英文页面及凭据弹窗断言，删除未使用的 `channelManageNote` 文案。没有另外增加语言切换器。

修复版最终复核：Admin 全量 **40 文件、596 项通过**，渠道专项 **17 项通过**，类型检查、构建、`verify:admin`、lint 通过（lint 有未修改知识库页面的原有信息提示，构建有原有大包提示）；Portal/operator 全量 Go 测试和 vet 通过，含 controller 的 75 项规格；运行时十个相关测试文件 **605 passed、2 skipped**，跳过的是 Windows 不适用的 POSIX 权限位用例。新增反例已确认在初版失败、修复后通过。此轮没有重做真实平台或集群验收。

## 本地试用步骤及预期

| 步骤 | 操作 | 预期 |
| --- | --- | --- |
| 1 | 管理员进入系统管理的渠道页 | 能看到员工选择及飞书、企业微信、微信三行，不依赖员工已经有企微标记 |
| 2 | 对未启用渠道点击“启用接入” | 保存开关，反馈等待生效；运行时未就绪时不允许提交凭据 |
| 3 | 等待员工更新并刷新 | 可用状态来自真实 runtime provider gate；旧版本/不可达显示错误或未知 |
| 4 | 配置飞书/企微或微信扫码 | 提交到所选员工；已保存密钥不回显，更新时留空可保留旧密钥 |
| 5 | 微信扫码后点“检查扫码结果” | 获取真实平台确认；有验证码要求时由用户填写。关闭会取消扫码会话 |
| 6 | 平台内向机器人发消息 | 收到真实回复；凭据认证或进程运行状态不能替代这一项 |
| 7 | 已关联用户、未关联访客及停用用户分别请求 | 按现有治理策略验证身份、工具和资料范围；本次渠道入口不新增权限绕过 |
| 8 | 更新凭据、重连、停用、重新启用 | 修改到正确员工；停用后不再收发，重新接入需要凭据；重启后配置按已有存储恢复 |
| 9 | 使用非管理员调用渠道管理 API | 拒绝；管理员角色撤销后也拒绝，不信任缓存中的旧角色 |

异常排查：

- 等待配置生效：核对 CR 字段是否保存、operator 是否运行及员工是否已 rollout；不要重复输入密钥。
- 运行时管理授权失败：核对 Python 运行时是否包含本次配套修改，以及 Portal/运行时使用的 per-employee internal token 是否匹配；不输出 token。
- 工作进程运行但未连上：检查平台应用发布范围、事件订阅、应用权限、凭据及网络。管理页从运行时 `connected` 字段判断连接，不自行推断收发完成。
- 微信扫码不可用：检查目标镜像包含上游微信 QR 能力、单 worker 条件和账号/平台支持范围；不能拿企微凭据填微信入口。
